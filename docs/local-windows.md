# Windows 本机运行版

适用于当前 `G:\tagent`，仅供这台电脑使用，不是公网部署。前端使用独立的预构建产物，后端运行编译后的代码，不使用开发热更新。邮件登录、收发和邮件验收本轮不执行；启动和查看页面不会自动进行模型或搜索测试。

## 日常使用

在 `G:\tagent` 打开 PowerShell：

```powershell
pnpm local:start
pnpm local:status
```

访问 [TAgent](http://127.0.0.1:3000/)。服务隐藏运行，关闭启动终端不停止它；重启电脑后需再次启动。没有安装系统服务或开机自启。

先在页面停止正在运行的任务并等待保存，再执行：

```powershell
pnpm local:stop
```

停止只处理此启动器记录且 PID、进程启动时间、Node 路径仍匹配的进程。它不删除历史、不卸载依赖、不停止其他项目。停止进程不撤销工具操作，意外中断仍可能产生模型费用；异常退出的任务下次启动按现有恢复机制标记中断，不自动重跑。

## 更新代码

```powershell
pnpm local:stop
pnpm local:build
pnpm local:start
```

构建使用已安装依赖；缺少依赖时按 README 的锁文件安装步骤处理，不自动安装任何 Skill/MCP。构建失败不会自动启动旧版本。构建后不要手动替换 `.next-local` 或在本机版运行期间重建 Server/Core；这不是自动版本升级系统。

原来的 `pnpm dev` 和本机版使用相同端口和用户数据，不能同时运行。启动遇到端口占用会拒绝，不会擅自关闭已有服务。不要另开一个后端连接同一 `.tagent` 数据目录。

## 数据和配置

| 内容 | 路径 |
| --- | --- |
| 项目与依赖 | `G:\tagent` |
| 后端配置 | `G:\tagent\packages\tagent-server\.env`，原文件不改写 |
| 会话、Agent、Skill/MCP 和搜索设置 | `G:\tagent\.tagent` |
| 前端本机产物 | `G:\tagent\packages\tagent-web\.next-local` |
| 启动日志、进程标识和构建回执 | `G:\tagent\output\local-app` |
| 运行临时文件和 Node 缓存 | `G:\tagent\.tmp\local-app` |

本机启动器明确使用文件持久化：以进程环境的空 `DATABASE_URL` / `REDIS_URL` 覆盖未启用的数据库配置，数据根目录固定到项目根。模型配置和已确认的搜索来源继续保留。切换 PostgreSQL 或独立数据目录应按正式部署步骤操作，不使用此固定本机入口。

启动器不改系统 TEMP、证书、代理、防火墙或账户；依赖已有 Node/pnpm，不复制安装一套运行时。浏览器自己的用户缓存仍由浏览器管理，不能保证所有第三方程序都不使用 C 盘。

## 访问边界

- 前端只监听 `127.0.0.1:3000`，后端只监听 `127.0.0.1:3001`。
- 前端通过构建期地址 `http://127.0.0.1:3001` 调用 API；本机版产物与默认 `.next` 分开，不能把它部署到其他设备。
- 后端使用现有 loopback 安全策略（`NODE_ENV=development`），但运行的是编译文件而非 watcher。它不是 HTTPS 生产模式。Host、Origin、工具审批和限流保持生效。
- 原配置有访问码时继续要求访问码，不会移除认证；设置了 HTTPS public origin 则拒绝此本机启动方式。
- 未设置访问码时，同一台电脑上的其他程序也能访问实例。不要做端口转发或通过反向代理公开此本机模式。

需要局域网或公网访问时，另按 [单实例访问保护](./self-hosted-access.md) 设置独立访问码、HTTPS 和代理，不放宽本机白名单。

本机启动成功只说明部署和页面可访问，不代表真实办公交付质量全部验收通过。剩余内容质量问题见 [验收清单](./release-readiness.md)。
