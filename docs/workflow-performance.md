# 长任务工作流验收

更新时间：2026-09-14。目标仍是 implementation_plan.md 中的流畅工作流看板，不能把列表减负或静止视口的流畅动画当作完整的 60fps 验收。

## 当前实现

- 关闭桌面工作流侧栏时卸载内部视图，不在零宽度容器中继续渲染全部事件。运行中手动收起不会被下一条事件重新打开。
- 实时分组和事件日志超过80条时使用 TanStack Virtual，根据实际行高渲染可见条目及预留区；保留总数、事件序号和全部数据。键盘 Home/End 能定位首尾，关闭/切换后保留滚动位置及测量缓存。
- 事件日志增加当前任务内的搜索，可匹配摘要、Agent、子任务、工具和事件类别，包含未挂载到页面上的事件。搜索不发起后端请求、不生成或保存任何内容。
- 架构按同一事件快照建立 Agent/任务索引，避免每张卡片反复扫描全部记录。重用同一个常驻 Agent 的不同任务、旧记录歧义、大小写和 run 边界保持原语义。
- 图模型仍包含全部节点和关系。长关系只绘制与当前视窗相交的部分，包括两端节点都在屏幕外但中间经过视窗的线段；平移后重新绘制，不要求点击。完整路径保留在关系元素的 `data-full-path`，真实目标处才显示箭头，不在裁剪边界制造箭头。
- React Flow 继续负责节点、端点和完整关系，静态连线统一在一个 SVG 中绘制。流动效果由独立、与视窗同尺寸的 Canvas 批量绘制，不再为每条关系创建持续运行的 SVG 动画；并未更换图形库或把图模型转成位图。
- Canvas 通过标准 Path2D/矩阵读取同一 SVG 的几何，只有关系、视口、尺寸或主题变化时重建路径。适配屏幕像素比，页面隐藏、组件卸载或减少动态效果时停止请求动画帧；静态关系和箭头始终保留。
- 长工具和综合输出连线也接入可见区域裁剪。全景缩放下限降至0.001，线宽随比例收窄，箭头按图形坐标缩放；默认仍以100%打开，节点选择器可恢复可读比例。极长图全景是位置总览，不保证每张卡片文字同时可读。
- 会话接收SSE时按网络片段内最多128个事件发布一次状态；片段结束和终态立即发布，不等待后续网络或另加定时器。只合并客户端更新次数，不合并、截断或改变WorkflowEvent本身。忽略的兼容回调和重复事件不再触发无意义的会话刷新。

虚拟列表采用库的动态测量与快照接口，避免自行实现滚动算法。相关原始文档：[TanStack Virtualizer](https://tanstack.com/virtual/latest/docs/api/virtualizer)、[React Flow 性能建议](https://reactflow.dev/learn/advanced-use/performance)。

## 已取得的证据

### 2026-09-14 连续事件接收

- 2,000条同片段事件只发布16次消息更新；完整顺序、事件ID、中文、最终结果、保存失败提示保持一致，之前发布的快照不被修改。跨会话归属校验仍在入队前执行，退出登录不会重新发布排队的私有内容。
- JSON解析失败、跨run事件和非文字的回复片段出现时，先保留该片段之前的有效材料，再显示未完成说明。终态不等待EOF，断流不遗留运行中状态；原有同时运行、定向停止和迟到历史回包回归继续保留。
- `verify-workflow-runtime.mjs --serve --task-agents --burst` 使用真实后端和SDK、本地固定模型，每个子任务一次返回40个read_url请求。全部私有地址读取由现有边界拦截，不访问外网。两个任务入口、父子继承与重启验证共14次本机模型请求；不是40次付费请求，也不代表搜索质量。
- 浏览器 `verify-workflow-live-browser.js` 通过原生SSE发起另一次任务，架构保持打开，在运行中看到40、51、80的工具计数变化；193条事件、80次工具请求与80次工具结果完整，最终报告与保存记录一致，日志可检索全部结果。该次为开发构建，采样平均18.9ms、P95约33.4ms，不能作为生产60fps或219节点实时增量验收。
- 当前正常编排计划上限是6个子任务，前面的72执行实例静态压力样例是展示层容量测试。没有为获得大图测试结果放宽编排上限、工具权限或预算；大图实时增量和真实办公任务仍需独立验收。
- 后续390宽手机检查可检索80/193条事件，没有横向溢出，截图已核对；这一轮完整 `pnpm check` 的78文件880项回归、四包类型/lint、生产构建与隔离HTTP/中断恢复通过。下方870项为批量绘制阶段的历史基线。

完整 `pnpm check` 已通过78文件870项回归、3项校验器自检、四包类型/lint、生产构建及隔离HTTP/模型异常/中断恢复。第一次校验发现动态线宽变量不符合已有主题token契约，现改用SVG属性计算并通过原测试，没有放宽检查。

## 重复运行

构建后在独立端口启动 Web。不要向正在使用的工作区提交压力任务。使用专门的 Playwright CLI 浏览器：

```powershell
npx --offline --package @playwright/cli playwright-cli -s=workflow-scale open http://127.0.0.1:3100
npx --offline --package @playwright/cli playwright-cli -s=workflow-scale run-code --filename scripts/verify-workflow-scale-browser.js
npx --offline --package @playwright/cli playwright-cli -s=workflow-scale close
```

`?baseline=1` 只用于旧构建诊断，跳过新行为断言；不能用于宣称优化后通过。原生SSE脚本使用 `verify-workflow-runtime.mjs --serve --task-agents` 返回的临时地址，默认允许的 Web 来源是3000；其他端口需先明确配置夹具来源，不应放宽产品 CORS。

连续事件验收：运行 `node scripts/verify-workflow-runtime.mjs --serve --task-agents --burst`，在专用浏览器打开 `http://127.0.0.1:3000/?workflowFixture=<返回的base>`，再执行 `run-code --filename scripts/verify-workflow-live-browser.js`。必须使用新浏览器会话与隔离端口；结束关闭浏览器，并向夹具返回的stopUrl发送POST以清理临时服务和数据。
