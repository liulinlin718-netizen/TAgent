# 回复与 Word 交付

更新：2026-09-14。本功能把已经结束的单条回复转换成可编辑的 `.docx`，不是新的模型任务、完整会话备份或质量认证。

## 用户入口

有正文且已停止生成的 assistant 回复下方提供“下载 Word”。用户提问、空回复和运行中的回复不提供下载。失败、中断和分支引用也可保留为文件，但文件明确显示对应状态；缺少成功记录时不推定任务成功。

点击后才加载生成器，在浏览器本地转换当前回复，不调用模型、读取外部链接、重跑工具或写入后端。界面只提示已交给浏览器下载，不宣称操作系统已经成功保存。生成失败可手动重试；切换会话或回复变化后，迟到的生成结果不会自动下载。已有计算结果的 Excel 下载继续独立保留。

## 文件范围

- 正文使用标准 Markdown/GFM 解析，保留标题、粗体/斜体、代码、引用、列表起始编号、多层缩进、任务清单、表格和原生 Word 脚注。表格保留全部单元格，长内容自动换行，不用截图替代可编辑文字。
- 正文 HTTP(S) 链接可点击，并在附录保留可打印的完整地址；不访问链接。图片仅保留说明与地址，不下载图片。HTML 作为原始文字保存；相对地址、非 HTTP(S) 或含凭据的链接仅保留文字，不启用跳转，附录列出转换提示。
- 文件包含消息/run 标识、当前可见的运行/保存/核对状态、办公检查结果与原因，以及已有的调研日期、来源 URL、来源日期依据、读取状态和旧来源标识。不复制其他消息、模型原始核对回执、旧修订稿或来源正文材料。
- 保存状态未知时明确写“未在本入口核实”，下载不代替后端保存。已有检查未通过或不完整时原样保留，不能用文件成功生成覆盖失败状态。
- SHA-256 仅对应导出前的原回复 Markdown；UTC 导出时间不是调研日期。文件可编辑，哈希不是签名、不可篡改证明或对修改后文件的认证。

普通正文使用11.5磅、核对附录10.5磅。默认 Letter 纵向页面，超过6列表格改为横向；有表头、边框、页码和独立层级，不设置会裁剪内容的固定行高。长附录可继续分页，不删掉失败项以压缩页数。

## 明确限制

正文上限200000、正文与所选记录合计400000个 JavaScript 字符串计量单位，附加记录最多1000项。AST 最多20000节点、32层；列表/引用最多8层；单表最多1000条数据和12列。超限或不支持的结构明确报错，不静默截断。XML 不可保存的字符拒绝导出；合法中文与 emoji 可保留。

脚注内表格暂不支持导出，需移至正文。尚无 DOCX 输入、模板套用、图片嵌入、公式/图表、PPT 或产品内 PDF 导出；也不是完整报告编辑器。未验证的来源仍然未验证，实际六角色办公交付质量仍见 [上线清单](./release-readiness.md)。

## 页面排版修复

验收发现旧手写 Markdown 解析器会压平嵌套列表，部分表格尾列被丢弃。回复改用已有 React Markdown/GFM，保留整体气泡、章节分隔与缩进，补齐表头宽度以保留尾列。每条回复的脚注标识独立，来源注释不会跳到另一条消息；来源注释标题使用中文。没有靠隐藏内容解决溢出。

## 验收证据

```bash
pnpm exec vitest run packages/tagent-web/src/app/__tests__/report-export.test.ts packages/tagent-web/src/app/__tests__/markdown.test.tsx
node scripts/verify-office-runtime.mjs --serve
pnpm check
```

- 16项导出回归用独立 ZIP/XML 解析器检查真实 DOCX：正文/Unicode、列表编号、65行表格、超出表头的尾列、脚注、来源日期、旧来源、失败/未保存状态、容量与链接安全。正文解析另新增5项回归；两文件共26项通过。
- 办公运行夹具扩为7场景、26次本机模型请求，覆盖已有六类协议与新的表格/嵌套列表/脚注回复。真实后端、SDK、SSE、保存和重启检查通过；模型回答与核对结论仍是固定夹具，不代表真实模型质量。
- `verify-word-export-browser.js` 配合隔离后端和独立浏览器会话，实际下载5次，覆盖失败回复、未完成核对、历史重进、手动重试、生成时切换会话和手机。1440/390/320及暗色截图检查通过，浏览器验收没有写入 API 请求或用户后端请求。
- 4份实际下载文件经本机原生 Word 只读打开并转 PDF，最终分别为3/2/1/3页；9页均渲染检查，中文、列表、表格、脚注、链接与失败说明未越界。测试脚本发现已有 Word 进程时退出，仅关闭测试文档；出现其他文档或可见窗口时不退出 Word。
- 本机缺少 LibreOffice，通用 `render_docx.py` 未能运行；本轮采用原生 Word 与 PDF 渲染检查，不能声称完成 LibreOffice/WPS、所有字体或跨设备兼容认证。PDF/PNG仅为私有测试证据，不是产品新增 PDF 下载功能。
- 完整 `pnpm check` 通过87文件1105项回归、25项脚本自检、四包类型/lint、生产构建和隔离 HTTP/中断恢复。测试材料位于私有 `output/playwright/`，不发布为真实业务报告。

原 [办公核对](./office-delivery.md)、[数据分析](./data-analysis.md) 和 [实施方案](../implementation_plan.md) 的边界不变；没有修改用户模型配置、搜索来源、Skill/MCP 绑定或自动安装外部工具。
