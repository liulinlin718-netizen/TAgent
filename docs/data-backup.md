# 文件数据备份与恢复

适用于单实例自托管、`/api/health` 中 `persistence: file` 的部署。此流程不适用于 PostgreSQL，不是在线快照，不代表主机故障、数据库备份或完整上线验收已经完成。

## 范围与前提

- 使用 `scripts/data-backup.mjs`，仅 Node 标准库，无依赖安装、模型调用、网络上传或自动停服。备份时逐文件复制并计算 SHA-256，完成前重新核对源目录和备份的完整清单与哈希。
- 包含指定工作区根目录下完整 `.tagent/`：会话、消息、费用、检查点、常驻/任务 Agent、Skill 文件包、MCP 配置和执行记录等实际存在的文件。目录中的日志也包含在内，不仅是团队配置导出。
- **包含私有内容和 MCP 凭据，未加密、未脱敏。** 必须放在仅管理员可访问且已加密的备份位置，不要放进代码仓库、公共云盘链接或发送给第三方。POSIX 下新目录0700、文件0600；Windows 应单独核查目标目录 ACL，本工具不修改系统权限策略。
- 不包含 `.tagent/` 外的工作文件、输出文件、部署 `.env`、证书、模型密钥、PostgreSQL 或 Redis。它不会读取 `.env` 来判断后端类型；已知 `DATABASE_URL` 环境变量非空时直接拒绝。使用者仍须核实实际存储和数据根目录，不能以存在旧 `workspaces.json` 代替核实。
- 先停止所有使用该目录的服务、CLI、watch 重启器及其他写入者，再执行备份。`--offline` 与 `--file-store` 是操作者确认，不会停止进程、取得跨进程锁或自动证明离线。两次校验只能发现部分并发变化，**不能把仍在运行的服务当作一致性备份**。
- 建议使用与备份时相同的应用版本恢复。应用版本、部署环境与外部文件须另行安全留档；本格式不是数据库迁移或跨版本兼容承诺。

## 备份

在停服前查看 `/api/health` 并记录真实 `TAGENT_WORKSPACE_ROOT`。未设置时，数据根目录为项目根目录。备份父目录应事先准备好；以下路径仅为示例，目标目录必须不存在且位于工作区之外：

```powershell
node scripts/data-backup.mjs create --workspace 'G:\tagent' --output 'D:\private-backups\tagent-20260914' --offline --file-store --include-private-data
```

仅成功复制和校验后写入 `manifest.json`。它包含格式版本、离线声明、时间、相对路径、文件大小与哈希，不包含文件正文或源机器绝对路径。成功命令输出 `ok: true`；失败返回非零状态，未完成目录保留供检查，不自动删除或覆盖任何已有备份。

定期验证已保存的副本，验证不会改写备份或调用模型：

```powershell
node scripts/data-backup.mjs verify --backup 'D:\private-backups\tagent-20260914'
```

哈希校验用于发现丢失、损坏和意外改动，不是签名、来源鉴定或恶意内容安全审计。只恢复来自自己可信存储的副本。

## 恢复到新目录

不会原地覆盖或合并。目标即使是已存在的空目录也拒绝，原目录和备份始终保留：

```powershell
node scripts/data-backup.mjs restore --backup 'D:\private-backups\tagent-20260914' --workspace 'G:\tagent-restored-20260914' --offline --file-store --include-private-data
```

恢复前校验完整备份，复制中再次校验每个文件。临时内容位于 `.tagent-restore-incomplete`，全部通过后才发布为 `.tagent`。中途退出、写入失败或配置不合法时，不应启动此目录；当前后端会拒绝带该标记的目录，避免误创建空工作区。保留失败现场，换一个新路径重做恢复，不手动移除标记绕过检查。

MCP 的旧 `executionApproved` 授权会撤销并更新配置 revision，其余凭据/参数保留；需要在新环境重新核对可执行文件、目录与变量，再通过管理中心显式授权。恢复本身不会启动 MCP、安装包、重跑模型或续跑任务。原始备份仍保留原配置，其哈希不变；`restore-receipt.json` 记录所用清单哈希与撤销授权数量。

确认命令成功后，先用隔离端口、恢复目录和受控环境启动同版本后端，核对工作区、消息、来源、费用、Skill/MCP 和 Agent。不要让测试进程继承生产 `DATABASE_URL`，不要与原实例共用数据目录。确认恢复符合预期后，再由管理员停服并将部署 `TAGENT_WORKSPACE_ROOT` 切换到新目录；本工具不自动切换或删除旧数据。

异常退出前的已落盘检查点也会备份。启动恢复实例沿用原有“标记中断、保留材料、不自动重跑”的逻辑；不能恢复尚未落盘的内容，也不能保证外部动作未发生或供应商没有计费。

## 验收证据与限制

- `node --test scripts/data-backup-self-test.mjs`：22项回归覆盖完整字节/空目录/二进制附件、确认门槛、原目录保护、恢复撤权、损坏/缺失/额外文件、路径穿越、Windows设备名与ADS、大小写冲突、符号链接/junction/硬链接、错误脱敏和失败不发布。
- `node scripts/verify-server-lifecycle.mjs`：实际生产后端、独立临时文件目录，无外部模型。停服后备份，恢复到另一个目录再启动，逐项比对中文消息、最终结果、Trace、费用、Fork、Skill/MCP及搜索设置；验证不完整恢复被拒绝且不生成空数据。全部纳入 `pnpm check`。
- 每份清单上限16 MiB、100,000条，单文件32 GiB、总计100 GiB；通过64 KiB缓冲复制。拒绝链接和跨平台名称冲突，不静默跳过。大型文件、极深目录、网络文件系统和跨平台恢复仍需针对目标环境验收。
- 磁盘满、主机断电/文件系统损坏、恶意本机进程、在线一致性、保留/轮换/异地恢复、PostgreSQL实际备份恢复仍是开放门槛。刷新/同步与独占文件创建使用 [Node 文件系统接口](https://nodejs.org/api/fs.html)，不将文件写入成功当作主机级持久性证明。

用户正在使用的3000/3001服务未被本轮备份或恢复，没有复制现有用户数据到其他位置，也没有修改其模型密钥、搜索来源或工具权限。
