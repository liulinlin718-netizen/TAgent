# 模型连接诊断

更新：2026-09-15。入口是管理中心的“模型连接”，本地地址 `http://127.0.0.1:3000/management/model`。用于分开核对部署配置、模型短请求和调研搜索，不把前后端启动成功当成 Agent 已能完成任务。

## 查看与确认

打开页面、刷新状态或点“连接测试预览”都不会调用模型。预览不写入测试记录，只在服务端内存保留最多5分钟的确认凭证；修改部署配置或重启后需重新预览。页面不显示或修改 API Key。

用户必须阅读接收方、模型、固定文本、预计费用，勾选同意，再点“确认并测试”。一次确认只发起一次模型请求：

```text
Reply with exactly TAGENT_CONNECTION_OK.
```

- 不发送会话、工作文件、Skill 或 MCP 内容，不允许客户端替换提示词、工具、密钥或服务地址。
- 输出上限64 tokens，无工具调用，不自动重试。请求等待上限是 `TAGENT_LLM_TIMEOUT_MS` 与15秒中的较小值，直到收到完整响应正文；保存耗时另计。
- 估算使用仓库中的模型价格，不是实时账单或费用硬上限。未知价格显示未知，不当作免费。超时、取消或网络错误不保证服务商没有计费。
- 单实例最多一个连接测试，两次新测试开始至少间隔30秒。不会自动定时测、排队或替用户重发失败任务；这不是全平台请求限流或硬预算。

“已收到完整短回复”只表示本次无工具短请求正常结束，不要求模型严格回显指定字符串，也不证明后续任务、搜索、浏览器、工具调用或办公交付质量合格。首页入口采用中性连接图标，不再固定显示绿色在线标志；空会话状态为“尚未开始任务”，不把欢迎动画标成 Agent 正在忙碌。

## 错误与处理

| 状态 | 核对事项 |
| --- | --- |
| 配置不可用 | 由部署管理员核对 Provider、对应 API Key、模型名称、服务地址与后端环境变量；部署环境优先于 `.env` |
| DNS / 连接错误 | 核对模型服务地址、代理和网络；不要把搜索源能访问当成模型 API 可访问 |
| TLS 错误 | 核对证书、系统时间和可信代理；不要关闭证书验证 |
| 认证 / 权限错误 | 核对密钥所属服务与模型权限；服务商401不清除 TAgent 登录 |
| 限流 / 余额 / 超时 | 核对服务商限制与账单，再由用户决定是否重试；不会自动增加调用次数 |
| 有响应但短回复未完成 | 核对模型/接口兼容性与输出限制；收到正文不等于任务成功 |

错误复用服务端分类器，页面和持久记录不保留服务商原始错误正文、模型输出或密钥。仅保留安全原因、服务商、模型、配置地址、开始/结束时间与已收到用量。服务地址本身属于部署信息，应按私有配置管理。

`GET /api/health` 继续报告 `configured` / `connectivity: unchecked`，不从一次历史短请求推断“现在在线”。调研搜索通过独立的 [调研搜索管理](./research-search.md) 配置和测试；Skill/MCP Discovery 又是另一条链路。

## 保存、停止与恢复

先持久保存开始记录，再发送模型请求。开始记录写入失败不调用模型；保存过程中收到停止请求，则保存取消结果，不再发送。请求已发出后的停止会中断支持取消的 SDK，不撤销服务商已经处理的请求。

响应丢失时页面阻止继续提交，用户先刷新核对已有结果。服务端用确认凭证的哈希识别同一次操作，重复提交只返回原记录；重启不自动重放。已知用量被保留，没收到完整用量则显示“费用待核对”，不虚报零费用。

最终结果写入失败时，页面保留结果并提供“重试保存”。此操作只补本地保存，不重新调用模型；未保存结果存在时禁止开始新测试。进程结束会失去尚未落盘的结果，重启根据已有开始记录标记中断，不补造响应或账单。

文件模式使用 `.tagent/data/model-checks.json`，保留最近20条记录；确认原始 token 不落盘。损坏记录拒绝加载，不用空列表覆盖。当前仅支持同一数据源一个后端实例，不是跨进程锁或永久审计档案。测试费用单独显示，不计入某个办公会话，尚未进入全平台成本聚合。

## 接口

所有接口沿用实例访问控制。页面首次读取和轮询均只执行 GET，不自动触发收费。

| 接口 | 行为 |
| --- | --- |
| `GET /api/model-connection` | 配置、当前测试、最近记录与剩余间隔；不调用模型 |
| `POST /api/model-connection/preview` | 空JSON对象请求，返回固定文本、费用估算与确认凭证；`requiresConfirmation=true`、`willWrite=false`、`willExecute=false` |
| `POST /api/model-connection/test` | 只接受预览 `id`、`token`、`confirmed: true`；接收返回202，供应商错误记录在测试结果中 |
| `POST /api/model-connection/:id/cancel` | 停止该测试，不重新运行、不撤销外部费用 |
| `POST /api/model-connection/:id/retry-save` | 仅保存已经收到的结果 |

## 验收

共享类型 `ModelConnectionPreview`、`ModelConnectionCheck`、`ModelConnectionView` 在 Core 定义；管理器测试覆盖明确确认、过期、配置变更、防重、取消、损坏存储、保存失败、价格未知和访问控制。

后端构建后运行：

```bash
node scripts/verify-model-connection.mjs
```

脚本使用生产后端、临时数据根目录与实际 OpenAI/Anthropic SDK，仅连接本机虚构模型。两种 SDK 各测试成功、认证失败、正文超时与实际磁盘写入失败，共8次本机模型请求；核对单次调用、费用未知、重复确认、保存重试和重启不重放。该脚本已加入 `pnpm check`。

浏览器验收先运行脚本的 `--serve`，使用其打印的 `base`、`resetUrl`、`repairUrl`、`statsUrl` 在专用 Playwright CLI 会话打开 `/management/model?modelFixture=<base>&resetUrl=<URL>&repairUrl=<URL>&statsUrl=<URL>`，先快照，再执行 `scripts/verify-model-connection-browser.js`。请求转发隔离后端，不改用户配置；完成后使用打印的 `stopUrl` 关闭该测试服务。
