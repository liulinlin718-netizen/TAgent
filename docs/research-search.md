## 选择来源

普通用户可打开管理中心的“调研搜索”（`/management/search`）：

1. 查看“当前启用”和配置来源；选择待测试来源不会自动切换。
2. 阅读外发范围、接收服务与费用说明，勾选确认。确认不预选，切换选项或刷新后需重新确认。
3. “测试来源”只发送固定公开关键词 `AI agent research`，显示相关候选数、请求失败或无结果；不调用模型，不保存配置。候选可用不等于事实已经核实。
4. “确认并启用”才保存选择，只影响之后发起的任务；已开始的任务及子 Agent 保持原搜索源。

设置使用现有持久化适配器，文件模式为 `.tagent/data/research-search.json`。保存后重启恢复；并发修改会提示刷新，不覆盖其他页面的新配置。写入失败保留原状态；响应丢失时页面要求重新读取结果，不盲目重试写入。

部署环境变量优先于页面选择。设置了非空 `TAGENT_SEARCH_PROVIDER` 时，页面不可覆盖；合法的当前来源仍可经确认手动测试。希望由页面管理时，管理员应取消这个环境固定项并重启。无效值会明确报错，不自动选择其他来源。

首次安装使用 `.env.example` 时，该项默认保留注释，不会锁定管理页。2026-09-15回归先复现了旧模板把默认值误当作管理员锁定，再验证复制新模板、明确确认保存和文件重载后保留页面选择；未发出搜索请求，也不自动修改已有实例的 `.env`。

管理员也可在后端环境变量中指定，重启后生效：

```dotenv
# 管理员固定为现有 Bing/SearXNG 和已配置的 Tavily/Jina 等来源，页面不可覆盖
TAGENT_SEARCH_PROVIDER=auto

# 或显式选择 Parallel 官方免费搜索，不与上面一行同时设置
# TAGENT_SEARCH_PROVIDER=parallel
```

`auto` 不会自动选择 Parallel。现有 HTML 搜索在本机曾跳到地区首页，公共 SearXNG 实例也曾全部失败；没有结果不代表互联网上没有资料。模型 Key 不提供搜索服务。

`auto` 的主题后备查询现使用同一 Bing 服务的国际结果视图，保留完整主题和当前年月；初次结果足够时不追加该请求。引号、`site:` 等显式条件不被删除，HTTP 与浏览器共用查询构造；跳转改变查询时拒绝将其他问题的结果用作材料。搜索结果仍按原主题过滤，不将日期摘要当作已验证发布日期。Bing 本身会考虑语言与位置，见 [微软的结果排序说明](https://support.microsoft.com/en-us/bing/how-bing-delivers-search-results)；这里是公开网页适配，不是有服务承诺的搜索API。

`parallel` 使用 [Parallel 官方 Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp) 的 `https://search.parallel.ai/mcp` 匿名入口。官方将其定位为免费探索/轻量使用，生产或高额度需求需要另行评估账户与服务条件。本轮适配只使用匿名入口，不读取 `PARALLEL_API_KEY`，不会自动升级为付费请求。它是内置搜索适配器，不是向 MCP 管理中心安装、保存或绑定第三方包。

明确选定 Parallel 后，`web_search` / `web_research` 的搜索阶段遇到限流、超时、空结果均返回来源诊断，不自动转发到其他搜索服务；无效配置也不会自动降级为其他来源。网页读取仍连接候选站点，独立浏览器和其他工具遵循其工具权限，这不是全局网络目的地限制。搜索耗时与服务可用性受实际网络影响。

## 设置接口

- `GET /api/research-search/settings`：只读取配置、可选来源与确认版本，不联网。
- `PUT /api/research-search/settings`：接收 `provider`、`confirmed: true`、`confirmationVersion`、`expectedRevision`；只有持久化成功才发布新状态。
- `POST /api/research-search/test`：接收 `provider`、`confirmed: true`、`confirmationVersion`，不接受自定义关键词、URL、命令或 env。单实例最多一个测试同时运行，30秒内拒绝重复测试；与其他 API 使用同一登录和 Origin 保护。

测试结果不持久化为“永远可用”状态，也不改变健康接口的 `connectivity: unchecked`。前端断开不代表后端测试已取消；遇到重复测试提示应等待已有请求结束。

## 数据与安全

- 发送搜索目标、关键词和匿名关联 ID，不发送系统提示、完整历史、原始会话 ID、文件或模型 Key。不要将密钥或不允许外发的业务内容作为搜索关键词。
- 同一会话在两个运行 API 中使用稳定的散列关联 ID，子 Agent 和连续工具调用复用它；它仅用于搜索关联，不代表用户身份认证。
- 使用项目已有 MCP SDK 处理握手、JSON-RPC 和 JSON/SSE 响应，不执行远端脚本，不采纳服务端提示作为系统指令，也不暴露远端其他工具。
- 请求固定在官方域名，沿用 DNS/公网地址、TLS、重定向与响应大小检查，不关闭证书验证，不访问内网。单次搜索包含握手最多 25 秒、响应最多 256 KiB；失败与完成均关闭连接。完整调研还需读取网页、调用模型，不受这个单次搜索时限保证。
- 搜索返回的标题、摘要及日期都是候选线索。`web_research` 仍读取原网页并独立解析发布日期、正文与引用；旧资料不能因搜索时间为今天而变成最新资料。
- 既有 Skill/MCP 导入继续走预览、风险扫描、用户确认，本设置不改变这些保存/执行约束。

OpenClaw 的 [Web 工具文档](https://docs.openclaw.ai/tools/web) 同样区分搜索服务与浏览器自动化。浏览器负责打开/操作页面，搜索质量取决于实际搜索提供方；不能仅因都采用 Playwright 就认定搜索能力相同。TAgent 不依赖 Codex 内部搜索、登录凭据或插件运行时。

## 原文追溯

`web_research` 不再只追读首批两篇页面的一层引用。搜索页面与正文中的原文链接共用读取额度：一次最多尝试8个页面，其中引用补读最多4个、最深两层；HTTP失败后的浏览器后备和重定向可能产生额外请求，这不是8次网络请求上限。后续搜索批次也能提供原文线索，最多两个页面并发，不递归遍历整个网站。

- 在已读取且主题相关的正文里，短引用可以借助父文章的上下文进入候选；落地页面仍独立检查正文、相关性和发布元数据，不继承父文章的日期或事实。
- 已识别发布方域名的相关链接优先补读，但域名优先级不是内容可信度证明。无日期、过期、无法读取或偏题的来源不能冒充近期证据；父子关系保留为 `discoveredFrom`。
- 读取状态按本次记录区分已读、失败、偏题、未读，避免把已经读过的引用一律提示成未读。单独 `read_url` 只抽取引用，不自动读取其目标。
- 多个入口跳转到同一最终地址时，只占一个材料名额，未满足目标时继续读取其他搜索结果；并发读取中已取得的正文不会被另一次验证失败抹掉。保留实际请求过的 `requestedUrls`，引用状态可对应原链接与落地地址，Orchestrator汇总也保留这些记录。不根据页面自行声明的canonical地址编造跳转或读取事实；`ref`、`version`等可能表示内容版本的参数保留，不当作追踪参数删除。
- 浏览器HTTP错误页、已识别的访问拒绝/验证页不作为可读正文；不点击验证、不绕过站点访问限制。来源受限时保留证据缺口。
- 报告的多源对照检查使用已知的上游引用链，不能通过不引用中间转载页，把同一原文当作两个独立来源。仅有目录链接到两家发布者，不会直接把这两家判为相互转载；通过此程序检查仍不是独立事实核查。
- 实际观察到的重定向关系也进入上游检查，避免旧文章地址跳转后断开引用关系；未知跳转、正文转载但不附链接的情况仍不能自动识别。

这些改动不切换搜索服务、不调用额外模型、不保存Skill/MCP，也不放宽URL/域名白名单与取消规则。原文页面自身受限、引用缺失、正文抽取失败和未识别的转载关系仍需在最终报告里说明。

## 验收

以下均从仓库根目录手动执行，不进入默认 CI 自动联网：

```powershell
# 固定公开场景：仅本次进程使用 auto 并清空搜索/仓库 Key，不改用户服务或 .env
pnpm exec tsx scripts/test-search.ts --free-only
pnpm exec tsx scripts/verify-live-research.mts --free-only

# 仅向 Parallel 发送一次固定公开关键词；隔离内存配置、不调用模型、不保存选择
pnpm exec tsx scripts/verify-search-settings-live.mts --confirm-public-query

# 仅给本次 PowerShell 及其子进程设置，不修改已运行的后端
$env:TAGENT_SEARCH_PROVIDER = 'parallel'
pnpm exec tsx scripts/test-search.ts
pnpm exec tsx scripts/verify-live-research.mts
```

`verify-search-settings-live.mts` 检查真实测试路由且断言内存配置未改变；`test-search.ts` 检查真实候选；`verify-live-research.mts` 读取候选页面并把材料、日期、失败状态写入本地 `output/live-research-*.json`。均不调用模型。材料可读或数量达标不是事实核验，也不是整份调研合格。

`--free-only` 不将 Parallel 或已配置的 Tavily/Jina 作为后备来源，也不携带 GitHub Token。去掉此参数则继续使用原环境中的选择和搜索API，可能消耗第三方额度。候选脚本会检查全部指定场景，再对任何无候选场景返回非零退出码，不因第一个场景失败而漏测后续场景。
