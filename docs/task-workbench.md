# 办公任务准备与继续处理

更新：2026-09-14。落实实施方案 §4.5 的低门槛任务入口；不是六个 Agent 的能力认证，也不替代完整工作空间仪表盘。

## 当前流程

空对话首页提供调研、文档、数据、项目、邮件、汇报六类任务准备入口。侧栏对应入口打开同样的表单；用户仍可直接在聊天框输入任务。

| 任务 | 必要材料 | 默认交付要求 |
| --- | --- | --- |
| 调研报告 | 主题；参考来源选填 | 实际调研日期、来源日期/URL、可验证性、旧来源与待核实项 |
| 文档整理 | 原文或工作记录 | 摘要、进展、风险、行动，区分事实与计划 |
| 数据分析 | 数据、单位与口径 | 计算过程、变化、异常与缺失，不虚构因果 |
| 项目计划 | 目标、时间与资源 | 里程碑、任务、依赖、责任、风险与验收 |
| 沟通邮件 | 背景与必须传达的信息 | 可核对的邮件正文与行动请求，不实际发送 |
| 演示汇报 | 汇报材料与已有结论 | 逐页提纲、图表建议与讲稿，不声称生成了PPT文件 |

表单先生成可返回修改的纯文本预览，用户再点“填入草稿”。已有草稿默认在末尾追加；替换必须显式选择。只有随后点击聊天框的发送按钮才创建任务、调用现有 Orchestrator 和模型。打开表单、预览、取消、填入草稿均不创建 Session、不落盘、不调用模型或工具。

研究的时间范围为近30天、今天或不限时间，使用实际执行日期，不将准备任务当天固化到提示中。执行者仍由现有 Orchestrator 选择，不保证点击某个入口就锁定特定 Agent。工具权限、治理确认、搜索配置和费用策略均不改变。

## 草稿与状态

- 应用前再次核对工作空间、会话、原草稿和运行状态。目标切换、删除、原稿变化或目标忙碌时拒绝覆盖，并保留原内容。
- 任务及合并后草稿按 UTF-8 限制为64 KiB，不截断材料；后端配置可能设置更低上限，最终仍由服务端接收检查决定。
- 表单及聊天草稿只在当前页面内存中。关闭表单会丢弃尚未填入的表单内容，刷新/关闭浏览器不保存未发送草稿；不向浏览器持久存储写入办公材料。
- 普通入口处理粘贴文本，数据入口另支持XLSX/CSV/TSV读取预览：先选表及范围，确认后追加材料，最后仍需预览草稿和手动发送。原文件仅在后端内存读取，不保存；具体编码、大小、公式与外发边界见 [表格导入与分析](./data-analysis.md)。回复中实际计算记录可下载Excel，尚无通用附件库或Word/PPT交付，也不执行邮件发送或项目平台写入。
- 近期对话只来自当前工作空间，最多六条。本页持有的活动任务优先；旧的运行标记显示“状态待核对”，未保存内容显示“需核对”。“已有回复”不代表质量通过。
- 空对话停在任务入口顶部；有消息时保留聊天原有的跟随输出与阅读位置行为。表单内容内部滚动，标题/底部操作保留，预览和返回修改有明确焦点。

## 验收与复验

20项回归覆盖六类材料与交付要求、中文/emoji、相对时间、UTF-8上限、草稿冲突、忙碌目标以及真实状态归属。

浏览器验收使用 `scripts/verify-office-runtime.mjs --serve` 的独立临时后端和本机模型夹具，不读取真实密钥。先在专用浏览器打开前端 `/?runFixture=<脚本输出的base>`，再用 Playwright CLI 执行 `run-code --filename scripts/verify-task-workbench-browser.js`。结束时关闭专用浏览器，并 POST 脚本输出的随机 `stopUrl` 清理夹具。

已验证六个表单的准备/取消、必填材料、追加/替换、预览/返回焦点、手机导航衔接、初次打开与刷新不误滚到底部，以及1440/390/320宽度、320×520短视窗和暗色截图。脚本最后只显式发送一次固定数据任务，经过真实后端、SDK和原生SSE，核对唯一终态、保存的完整输入/输出及刷新后重新进入；准备阶段服务端写入为0，用户后端写入和真实模型调用为0。

这证明输入到受控运行的交互链路，不证明真实模型能够完成六类办公工作、研究来源真实可靠或项目已经可上线。完整开放项仍见 [上线清单](./release-readiness.md)。
