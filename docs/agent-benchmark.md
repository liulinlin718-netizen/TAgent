# Agent 评测边界与实跑内核

更新时间：2026-09-13。大厅保留免费配置检查和已保存任务复核，并已接入八题受控办公实跑的预览、明确确认、进度、取消、历史及过期成绩处理。协议和交互已通过隔离验收，真实模型成绩与完整办公质量尚未验收，不能据此宣布产品可上线。

## 三种不同的证据

| 模式 | 实际测量 | 不能证明 |
| --- | --- | --- |
| 配置检查 | Skill 声明、工具权限、职责和输出规则的覆盖 | Agent 实际会完成任务 |
| 已保存任务复核 | 同一运行的执行回执、工具请求、权限与交接记录 | 来源真实、结论正确或完整题库成绩 |
| 受控办公题库 | 当前 Agent Loop 在固定材料、指定输出契约和受限工具环境中的执行结果 | 真实网络/MCP/浏览器能力、开放式办公质量或外部榜单成绩 |

题库借鉴 [IFEval](https://arxiv.org/abs/2311.07911) 的可验证指令约束，以及 [GAIA](https://arxiv.org/abs/2311.12983) 对推理和工具能力的关注。这是 TAgent 自己的基础材料题，不复制上述题库，不复刻难度，也不具备对应榜单的可比性。角色题目前主要检查交付字段契约；开放式报告、邮件质量和真实文件交付还需要独立 rubric 与人工抽检。

## 题目与评分

每个 Agent 使用7道通用题和1道角色题，固定版本 `tagent-controlled-office / 1.0.0`。虚构材料的基准日期固定为2026-09-13，不能用它表示今天的资讯。

| 题目 | 核对要点 |
| --- | --- |
| 来源日期与范围 | 近30天一手来源、旧材料、无日期传闻、人数与来源地址 |
| 精确输出格式 | JSON字段、数组顺序、语言标签、数字类型、不附额外解释 |
| 材料读取与计算 | 实际读取指定库存材料、总数量、总金额和凭据 |
| 任务计划 | 三个任务、前置依赖、负责人和验收条件，不添加未要求任务 |
| 数据口径 | 万元与元不混淆、增长率、已知合计、缺失月份和未知季度总额 |
| 不可信材料 | 提取订单事实，不服从混入的安装/泄露指令，不声称已执行 |
| 交接 | 目标、已完成、风险、待确认问题和下一负责人 |
| 角色交付 | 六角色各自的字段契约，缺失日期、未发送状态与样本边界不得编造 |

每项检查保留维度、权重、结果和可读原因。整题必须满足所有约束才计入通过率；部分正确可获得部分分数，但不能因自称“100分”而加分。数值、数组和对象按结构比较，不用关键词拼凑质量判断；工具题必须有实际材料读取记录。已中断或模型请求失败的部分题库不产生整套总分，不删除缺失题以提高通过率。

七维分数由各维度检查权重归一化，再按既有角色权重汇总。当前分数仅适用于这组基础题，不能用于宣称某 Agent 是经过权威认证的全能助手。题目变体、抗记忆污染、难度校准和真实材料抽检仍需开发。

## 执行与成本

- `previewOfficeBenchmark` 不请求模型、不联网、不写文件。预览包含配置、Skill和题库指纹、模型/Provider/服务地址、外发范围、缺失Skill、调用限制和不覆盖的能力。
- `executeOfficeBenchmark` 必须收到显式确认和一致的预览；配置、Skill、模型或题库变化后旧确认失效。Core 方法是供服务器集成的接口，不是无需鉴权的 HTTP 入口。
- 复用正常任务的 `runAgentLoop`、Soul、运行策略与 Skill 格式化。`read_url` 在本模式明确替换为固定材料读取器，只接受当前题目指定地址；不发网络请求、不加载MCP、不运行脚本。允许工具仍取声明和白名单交集；人工确认只涵盖该固定只读工具，不扩大真实工具授权。
- 每题最多4次模型请求，全套最多32次，每次最多1024输出token、64 KiB请求消息与工具定义，整套180秒时限。调用、截断重写和最终综合共享限制，不自动重试供应商失败。
- 已知费用到0.50美元后停止追加请求，单题还受原Agent预算与0.15美元阈值约束。该检查基于已经返回的本地用量估算，不是供应商硬费用上限；正在执行的请求可能越过阈值，未知价格和未返回用量不能解释为免费。预览估算基于本地价格表，不作为账单承诺。
- 模型调用前保存请求意图；只有真正发起后才增加调用计数。保留未结算意图数量（可能尚未实际发送），以提示断连或进程故障后的费用不确定性。已返回草稿和用量在检查点失败时通过 `OfficeBenchmarkCheckpointError.unsaved` 保留，之后不继续调用模型。单次检查点最多等待10秒；超时不能撤销已开始的底层写入。Server 暂停新增评测，并通过查询接口返回本进程保留的未保存结果；不要直接刷新或重跑，应先核对存储。进程退出后无法保证恢复未落盘内容。

## 大厅与接口

打开“评分与证据”不会调用模型。先点击“查看范围与费用”，核对接收方、外发的 Soul/Skill/虚构材料、调用限制与费用不确定性；勾选同意后才可确认实跑。关闭窗口不取消已确认的后台评测，再次打开只查询同一运行；停止按钮中断后续工作，不能撤销已发出的请求或账单。

以下路径均位于 `/api/agents/:id/benchmark/live`，沿用现有登录与跨站请求防护：

| 方法与路径 | 行为 |
| --- | --- |
| `POST /preview`，正文 `{}` | 返回外发/成本预览、题目清单、5分钟有效的一次性凭证；无模型调用、无持久化 |
| `POST /start`，正文 `{confirmed:true,token}` | 复核凭证、Agent/Skill/题库/模型及连接配置；首个检查点保存后返回202 |
| `GET /history` | 最近20条简要记录、当前运行ID与存储故障状态 |
| `GET /runs/:runId` | 该Agent对应的结果、进度、失败原因、Trace、用量和保存状态 |
| `POST /runs/:runId/cancel`，正文 `{}` | 明确停止；重复停止已结束记录不重新执行 |

同一后端只允许一个评测运行或收尾，不排队、不自动重试、不接受客户端自报输出/分数/执行参数。预览凭证最多在内存保留50个，重启失效；连接配置摘要只在服务端内存比较，不回传API Key。单实例限制不替代普通任务、其他管理接口或多进程的全局费用控制。

大厅只在整套执行完成、保存成功、当前配置/Skill/题库/模型/服务地址均匹配时显示“Benchmark 实测 · 固定材料题”。旧成绩仍可查看，但不代表当前配置。新的失败或中断不会冒充完整成绩，也不删除此前仍有效的完整成绩；当前配置检查依然是独立免费记录，不把它写成实测。

## 记录与验收

`OfficeBenchmarkExecution` 使用单独的 `controlled_office` 模式，包含题库/配置/Skill指纹、模型、每题输出与检查项、用量及统一 `WorkflowEvent`。事件中的能力快照只显示实际加载的固定工具，不包含Soul全文或MCP凭据。原始模型Trace仍可能包含发送的Soul/Skill，不应公开。

文件模式检查点位于 `.tagent/data/office-benchmarks.json`，最多保留全局最近50条；查询显示每Agent最近20条，并非永久历史档案。JSONL位于 `.tagent/benchmark-traces/<runId>/`，尚无自动清理策略，应纳入私有数据备份和容量管理。写入成功后再发布新状态，损坏记录拒绝加载而不覆盖。重启将未结束的评测标为中断，保留已保存材料和用量，不自动调用模型。当前同一数据目录只支持一个后端实例。

后端/Core构建后可以运行无付费的隔离验收：

```bash
pnpm exec vitest run packages/tagent-core/src/__tests__/office-benchmark.test.ts packages/tagent-core/src/__tests__/office-benchmark-runtime.test.ts
pnpm exec tsx scripts/verify-office-benchmark.mts
pnpm exec vitest run packages/tagent-server/src/__tests__/office-benchmarks.test.ts
pnpm exec tsx scripts/verify-office-benchmark-api.mts
```

内核脚本用真实OpenAI兼容和Anthropic SDK连接本机模拟模型，覆盖六角色共12套题、134次本机请求及两个认证失败。新增API脚本启动独立后端，14次本机请求验证确认、成绩查询、重启、取消、崩溃恢复、模型失败与真实磁盘写入故障。答案由夹具提供；测试中的100分仅证明规则和协议能正确处理已知答案，绝不能写进真实Agent的实测成绩。所有持久化进入临时目录，结束后清理，不读取真实密钥、不修改用户会话。

API脚本加 `--serve` 可保留隔离服务供 `scripts/verify-office-benchmark-browser.js` 验收，结束后输入 `stop` 清理。浏览器覆盖确认前零调用、关闭再打开不重复运行、刷新后保留成绩、停止/错误提示，以及1440/390/320宽度截图和原有雷达/Skills侧栏隔离。最终65文件733项回归、三包类型检查与生产构建通过；Next工作区根目录及Recharts初始化尺寸警告仍存在。

## 剩余门槛

1. 质量：授权后的真实模型验收、每题变体、真实办公材料、开放式交付rubric、网页与MCP专门题型和独立人工抽检。当前基础字段题不替代这些门槛。
2. 运行保护：跨实例互斥、全局费用硬限额、长时间存储故障核对和更完整的取消/恢复组合。
3. 规模与证据：长期历史/Trace索引和清理、完整版本证据、大上下文与高并发性能、完整可访问性。

整个项目的发布范围继续以 [上线验收清单](./release-readiness.md) 为准，不能因受控评测链路通过测试就宣布产品可上线。
