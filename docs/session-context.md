# 连续对话、分支与原文引用

更新时间：2026-09-13。对应 implementation_plan 的会话上下文、Fork/Diff 与“结论摘取引用”，不实现自动对话 Merge。

## 当前行为

- 两个运行入口在接收任务时原子保存本次提问、运行标记及会话参考清单。参考内容来自提交前的同一会话快照，不接受客户端自报历史，不自动遍历父分支或其他会话。
- 规划、子任务执行、最终综合、办公交付核对均使用该快照。规划可选择所需消息标识；没有显式选择时，单任务使用当前快照，多任务默认取最初用户材料和最近四条。模型选材质量仍需真实任务验收。
- 默认最多12条、合计16000个 Unicode 字符，单条最多12000个。较老的首次用户提问在条件允许时保留，超长消息保留首尾并标记省略；消息没有从存储删除。遗漏数量、节选数量和内容指纹记录在 `run.context` 与 `context_loaded` 事件中，清单不再复制全文。
- 前文作为带来源类型的参考材料，而非历史工具协议。旧助手输出、摘要与引用不视为已验证事实或新的操作授权；工具仍走当前白名单和审批。历史 user 长度约束可按材料标识参与程序复算，旧助手/引用中的文字不能冒充用户长度要求。语义适用性、要求覆盖与事实判断仍有模型局限。
- 续问会把所选历史材料发给已配置的模型，增加正常任务的输入量；不会因此单独调用摘要模型。历史包含“最新”不自动迫使本次改写任务联网；本次明确要求最新信息仍走现有新鲜度与来源核对逻辑。省略材料、模糊指代及长会话检索质量不是本轮全部解决的能力。

## 引用流程

在来源分支打开“对比父分支”或“引用到主线”，查看完整原文，选择连续节选，再预览并确认。桌面左右对照，手机切换主线/分支；读取失败可重试，保存失败保留原文，不自动重试或调用模型。

1. `POST /api/workspaces/:wsId/sessions/:sourceId/quote-preview` 接受 `messageId`、`text`。仅允许同工作区内直接父子会话的 assistant 原文，单次最多8000个 Unicode 字符，任务运行中不可引用。
2. 预览返回原文、来源消息/会话、源内容指纹、位置、目标及确认指纹，固定 `requiresConfirmation=true`、`willWrite=false`、`willExecute=false`。该操作不保存、不生成内容。
3. 兼容路径 `POST /api/workspaces/:wsId/sessions/:sourceId/merge-to-parent` 现在必须提交原文选择、预览 `fingerprint` 和 `confirmed=true`。空请求不会再自动生成分支摘要；旧调用方需更新。
4. 保存时重新核对来源及运行状态，写入成功才发布。引用复制为父会话的新消息，保留来源哈希与原文位置；不改来源分支，不复制其工具协议或成本。同一源原文重复确认不会重复添加。

主对话显示“分支原文引用，未经独立核验”及来源入口。源会话删除后已确认的引用副本仍保留，来源入口不可用；这不是撤回或自动同步副本的功能。

## Fork 边界

- 完整 Fork 复制已保存历史，不继承运行控制归属，也不自动同步父分支后续消息。来源有未完成任务时拒绝复制，恢复或结束后可再创建。
- 摘要 Fork 通过独立窗口选择需完整保留的消息、预览外发范围与费用，再确认调用。模型从其余历史提取连续原文，程序核对每段来源，不接收改写、拼接或编造的“结论”；压缩材料标记为 `fork_summary`，不是金标准事实。原文一致不等于关键信息齐全或事实正确。
- 新建接口拒绝以 `parentSessionId` 或 Fork 类型创建空壳分支。树查询优先于会话参数路由，未知消息会话返回404；旧记忆查询深度限制为1至5，但该查询不会自动注入任务。

## 摘要确认与恢复

1. `POST /api/workspaces/:wsId/sessions/:sourceId/fork/preview` 接受 `preservedMessageIds`，返回待压缩消息、服务/模型/地址、UTF-8输入量、费用粗估和五分钟确认凭证。预览不调用模型、不保存；`requiresConfirmation=true`、`willWrite=false`、`willExecute=false`。选择完整保留的消息只复制到新分支，本次摘要请求不外发这些正文；以后在新分支继续任务仍按正常上下文规则发送材料。
2. 原 `/fork` 的摘要请求必须带 `forkType=fork_summary`、`confirmed=true`、`previewId`、`token`。服务重新核对来源指纹和连接配置，先持久化唯一操作，再调用模型。同一确认重复提交返回同一操作，不会重复生成；并发的其他摘要拒绝，不排队。完整 Fork 接口不变。
3. 单实例最多一个摘要操作，独立于普通任务并发名额。每次最多一次模型请求、2048输出token、90秒调用时限，不调用工具、不自动重试。历史最多1000条，待压缩输入最多64000 UTF-8字节；完整保留最多100条/8000 Unicode字符。每个来源会话最多20条操作记录，超限需保留历史并使用完整 Fork。
4. 返回内容必须含1至16段原文，单段最多1500字符、合计6000字符。空/截断响应、额外工具请求或引用核对失败都不创建空壳分支；保留已收到的用量与最多12000字模型原始返回。认证、连接、超时等使用安全分类提示，不回显供应商原始错误或凭据。
5. 模型结果与用量先保存为 `ready`，再原子创建目标分支并标记 `completed`。已知费用和tokens仅计入来源会话一次，新分支费用从零开始。未知单价或未返回用量明确提示账单待核对，不能把零已知费用说成免费；本地价格粗估不是供应商硬上限。
6. `GET .../summary-forks` 和 `GET .../summary-forks/:id` 返回操作、保存状态与可恢复性；`POST .../:id/cancel` 请求停止；`POST .../:id/retry-save` 仅重试本地写入，不调用模型。窗口显示历史、失败原文、已知用量、停止、打开分支和重试保存；关闭窗口不停止已确认操作，重开可查。新分支只有保存后才可打开。
7. 重启时 `ready` 只补做本地保存，`running` 改为中断并保留未结算请求标记，不自动续费重跑。保存失败的内存结果会通过 `persisted=false/canRetrySave=true` 返回；若尚未落盘就重启，原文和最终用量可能无法恢复。运行/待保存期间，来源会话拒绝新任务、删除、Fork及引用修改，前端保留草稿并显示查看入口。

摘要记录在来源会话内，不属于普通任务 WorkflowEvent；目前治理任务聚合不包含这类独立操作。停止不是撤销已完成的原子保存。当前仍为单实例文件持久化验收，不保证停电、损坏存储、跨进程互斥或供应商账单核对；不自动改写任何旧摘要。
