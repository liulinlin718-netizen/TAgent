## 统一入口

使用 Node.js 24（最低22.13）和仓库锁定的 pnpm 10.12.1：

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm check
```

`scripts/check.mjs` 按顺序执行，不使用 Turbo 构建缓存跳过本轮产物：

1. 构建 AI、Core、Server，随后再执行跨包测试，避免读到旧 dist。
2. 四包 typecheck 和完整 lint，保留现有 Web 的 Next/React 检查。
3. 校验器/文件备份恢复/源码候选自检与全部 Vitest 回归。
4. Web 生产构建。
5. 独立后端的生命周期、请求/连接限制、离线备份恢复、模型错误、连接诊断、实际表格计算、办公核对/修订、Skill/MCP 绑定权限与运行中断恢复验收。

任何步骤失败，后续步骤不执行，命令返回非零状态。校验器通过 Node 直接启动 pnpm CLI，不拼接 shell 命令；从脚本自身定位项目根目录。`pnpm test` 保留原有交互式使用方式，单独跑测试前仍需确保共享包构建最新。

根目录只有一份 workspace 定义，原 Web 子目录的构建脚本忽略设置已移动到根目录。Next 的 Turbopack root 指向 monorepo，能解析同级包；没有停用类型或 React 检查来隐藏问题。

## 数据与费用

- 校验器移除继承的模型密钥、Token、部署数据路径和前端API覆盖，禁用后端 `.env` 读取，使用自建临时工作目录；结束后清理该临时目录。
- 默认验收只使用固定响应、本机协议服务或缺少模型配置的降级路径；不安排真实搜索、付费模型、外部安装或自动部署。它不是操作系统级网络沙箱。
- `--ignore-scripts` 不执行依赖安装脚本；浏览器实际验收所需的 Chromium 环境另行准备。安装成功不证明任意第三方 Skill/MCP 可运行。
- 生产构建会更新本工作区的 dist/.next，勿与另一轮构建或测试同时写同一套产物。用户3000/3001服务不由校验器启动或停止；后台热更新由现有开发服务自行处理。
