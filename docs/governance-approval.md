# 工具确认与治理记录

更新：2026-09-13。本轮落实“普通用户能看懂并决定 Agent 的外部操作”，不替代完整上线验收。

## 执行模式

| Agent 设置 | 实际行为 |
| --- | --- |
| suggest | 每次工具调用都需要用户确认，包括读取已绑定 Skill 资料 |
| auto_edit | 仅受信内置工具元数据声明的本地只读操作免逐次确认；目前只有 read_skill_file，读取任务已绑定的内存资源，不访问磁盘、网络或执行脚本 |
| full_auto | 保留已配置白名单内的自动执行；不是绕过 URL 防护、MCP 独立执行授权或其他治理规则 |

未知工具、联网/浏览器工具和 MCP 不因名称带 read/search 就自动获得本地只读待遇。导入包不能声明该免确认权限。强制新鲜度预调研也经过相同审批，不先发搜索请求再询问用户。

本轮没有改变现有 Agent 的保存配置和默认模式。用户可在 Agent 编辑页调整，新任务按启动时的配置执行。

## 确认流程

1. 工具请求绑定 workspace、session、run、agent 和子任务，生成唯一 requestId，等待最多120秒。
2. 对话中显示工具、参数预览、所属 Agent 和确认期限，用户选择“允许本次”或“拒绝本次”。小屏工作流弹层提供“返回工具确认”。
3. 服务端核对请求归属和有效期，将决定加入同一组 WorkflowEvent，并等待任务检查点写入成功，之后才授予一次执行许可。
4. 取消、断连、超时、缺少处理器、确认回调失败或保存失败均不授予许可。写入有10秒等待界限，失败返回可读错误，不自动重试批准。
5. 已结束请求不接受再次批准。服务重启恢复任务材料和决定记录，但不恢复待批队列，不重新调用模型或工具。

批准仅表示获得本次参数的执行许可，不代表工具成功，也不撤销已经完成的外部操作。tool_call 表示请求，执行结果须核对 tool_result 和任务终态。等待确认期间停止任务仍可用。

参数预览限制为16 KiB，过深、过长或不完整的内容不能批准。env、认证字段、部分 URL 凭据和常见 token/password 命令参数在显示事件中遮蔽；这不是完整 DLP 或凭据保险库，不保证任意自然语言、工具输出或所有本地底层 Trace 都不存在敏感内容。原始执行参数不会被前端修改或替换。

## 查询与保存

- `GET /api/approvals?runId=...&sessionId=...`：只查询当前任务待处理决定，不执行工具。
- `POST /api/approval/:requestId`：只接受 `approved`、`runId`、`sessionId`，沿用已有访问保护。跨任务、重复、过期和无效请求拒绝处理。WebSocket 确认同样检查归属和登录状态。
- `GET /api/governance/events`：返回 events、stats、nextCursor；支持 runId/sessionId/agentId、limit（1–100）和 before 游标。同一响应中事件与统计来自同一查询快照。
- `GET /api/governance/stats`：保留兼容入口，与事件查询共用计算规则。

治理页不再读取另一份进程内日志。新任务从已保存消息及活动任务的 WorkflowEvent 查询；旧消息没有新版 run 回执时，按事件中已有的 run/session/event 标识回查，不补造标识或改写历史。Fork 复制的来源记录不是新任务，不重复计入费用。缺少可验证归属的旧日志不推断为当前任务。

统计数字是已记录决定，不是安全认证或全部检查次数；未知裁决不算通过。成本来自消息中已经保存的已知用量及实际时间，不是模拟曲线或供应商账单。按单 Agent 筛选不把整个任务成本归给该 Agent；一条旧消息包含多个 run、无法分摊时不重复计算成本。

页面支持显式刷新、按任务筛选、加载更早记录、查看参数和返回来源任务；读取失败时保留上一次成功数据并提示错误。待确认与批准事件分别保留，历史中“当时等待确认”不代表现在可继续批准。

这些记录依附来源会话。删除会话会移除其治理回查结果，不是防篡改或永久审计档案。治理统计现与Trace回查共用按提交版本缓存的WorkflowCatalog，仍从存储快照聚合；独立的事件明细已接入 [JSONL索引与分页](./trace-history.md)，并不等于治理统计数据库索引。大量历史、跨用户审批、细粒度凭据隔离、跨进程并发和完整替代方案决策链继续列入上线门槛。
