# Evidence-Bound Review 优化与开发计划

日期：2026-09-25。范围：独立的离线报告约束核查库与 CLI，不扩展为通用事实核查器或完整产品。

## 审查基线与结论

- 审查基线：本独立仓库提交 `9e1398d09e5e358289f59d1cc7e61a591bd742bc`，包版本 `0.1.0`，规则集 `evidence-bound-review/v1`。开始审查时工作区干净。
- 已读取实际源码、测试、中文 `README.md`、英文 `README_EN.md` 与历史验证记录。两个 README 是当前项目介绍，本轮不修改。
- 本轮只新增本计划；不修改产品代码、测试、主仓库内嵌副本，不提交或推送，不联网、安装依赖、调用模型或产生 API 费用。
- 已有基础值得保留：零运行依赖、确定性日历窗口、精确 UTF-16 引用、指令和参考材料分离、失败不伪装通过、明确 `factVerification: not_performed`。
- 当前最有价值的工作不是增加题型，而是修复可复现的规则误判、降低允许输入内的重复计算，并降低接入时的错误定位成本。

下面的 P1 是下一轮优先修复项，不代表已出现线上事故；P2 是紧随其后的正确性或接入改进。工作量为单名熟悉代码的工程师的工程日区间，包含定向测试，不是交付日期承诺。

## 发现与建议

### EBR-01：整句过滤和首个匹配会漏掉明确的串行冲突

**优先级 P1；预计 1–2 工程日；可行性中高。** 不需要模型或新依赖，但必须控制误报，不能简单地把所有逗号都切开。

证据：[src/grounding.js:4](../src/grounding.js#L4)、[src/grounding.js:11](../src/grounding.js#L11)、[src/grounding.js:44](../src/grounding.js#L44)、[src/grounding.js:50](../src/grounding.js#L50)、[src/grounding.js:51](../src/grounding.js#L51)。`definite` 将不确定性施加到整句；任何位置出现未来/假设词会跳过整句；`exec` 只检查首个行为候选。

本轮复现：

| 要求 | 报告 | 当前结果 |
| --- | --- | --- |
| 严格串行。 | 建议并行执行。 | 正常发现 `parallel_action`，作为正对照 |
| 严格串行，负责人未知。 | 建议并行执行。 | `no_findings`，串行规则甚至未激活 |
| 严格串行。 | 建议本轮并行执行，未来再优化质量。 | `no_findings`，未来词屏蔽当前建议 |
| 严格串行。 | 不建议设计和开发并行；建议开发和测试并行。 | `no_findings`，只检查了被否定的首个建议 |

影响：普通任务经常同时包含已知约束和未知负责人。当前结果不能稳定用于拦截已有能力范围内的直接冲突；免责声明不能替代这些基础正确性修复。

建议：建立轻量、保留原始偏移的子句和匹配区间；让否定、条件和时间范围只影响相应的候选行为；遍历全部候选，而不是首个 `exec`。条件跨逗号的关联不能丢失；无法确定作用域时记录跳过原因，不猜测完整语义。规则 ID 和结果字段尽量兼容，语义变化记录规则集版本。

验收标准：上面三个漏报样例均定位到实际冲突片段；现有假设、否定、引用、代码块例子不新增误报；“如果未来获批改变条件，可并行”仍不被当成本轮执行；返回 `quote === original.slice(start, end)`，CRLF/emoji 偏移不漂移。

### EBR-02：允许范围内的重复引用使同步检查出现明显长尾

**优先级 P1；预计 1–2 工程日；可行性高。** 先消除确定性的重复扫描，不通过提高输入上限、自动调用模型或直接增加 Worker 掩盖问题。

证据：[src/text.js:1](../src/text.js#L1) 每生成一个引用都重新切片并扫描前文计算行号；[src/index.js:80](../src/index.js#L80) 在每条缺少合格日期证据的引用中重新分段同一份材料；[src/index.js:85](../src/index.js#L85) 直到末尾才去重问题；[src/grounding.js:79](../src/grounding.js#L79) 和 [src/grounding.js:89](../src/grounding.js#L89) 也有关系遍历内的重复过滤和文本计数提取。

本轮单次有界探针：同一份 92,489 个 UTF-16 单元、1,800 个短句的合成材料，无发布日期元数据；报告片段唯一，引用重复且均为 `recent`。全部仍在当前输入限制内。

| 引用条数 | 本轮观察 | 结果 |
| --- | --- | --- |
| 1 | 约 716 ms | 1 个问题、1 条来源检查 |
| 16 | 约 5,058 ms | 去重后仍只有1个问题，却处理16条来源检查 |
| 128 | 子进程达到6秒保护上限，被终止 | 不记作检查完成；未测完整耗时 |

这不是统计性能基准，也不作为跨机器承诺。当前机器负载会影响绝对值，但源码和探针共同确认重复计算路径。若调用方直接接入 Node 服务，这些同步计算会占用其事件循环；本轮未宣称已有线上服务因此故障。

建议：每份材料只分段一次，预计算行起点索引；按材料 id 缓存首个上下文片段及日期评估；提前归并完全相同的引用，同时保留原始数量与唯一数量的区别；按数量/单位建立关系索引，并缓存每个报告子句的计数。所有缓存仅限单次调用，避免跨请求保留私有材料。

验收标准：同一材料的分段和日期评估次数与重复引用数解耦；1/16/128条完全重复引用保留相同问题和相同原文定位；同机固定探针中128条不超过1条耗时的约2倍加100 ms，先以操作次数和相对值为门槛，不宣称固定机器性能。已有总长度、语句数和引用数限制仍有效，超限不截断伪装完成。

### EBR-03：包含关系的歧义判定忽略单位和明确来源

**优先级 P2；预计 0.5–1.5 工程日；可行性高。** 只利用已明确的单位与来源，不推断集合身份，不引入知识图谱。

证据：[src/grounding.js:29](../src/grounding.js#L29) 已保存 `unit`、材料位置和来源标签，但 [src/grounding.js:79](../src/grounding.js#L79) 仅以 `total/part` 判断是否重复，并在来源筛选 [src/grounding.js:88](../src/grounding.js#L88) 前直接跳过。现有 [test/grounding.test.js:108](../test/grounding.test.js#L108) 只覆盖无明确归属、同单位的合理保守跳过。

本轮复现：只有“来源A：登记210份合同，其中30份到期”时，报告“来源A的210份是否包含30份？”会被正常指出。再加入“来源B：登记210家门店，其中30家暂停”后，同一报告反而变成 `no_findings`，原因是数字重复；单位和来源已明确不同却未参与判定。

影响：越是多材料的比较报告，越容易让本来可检查的字面关系全部失效。用户不应为了保留一个有效检查而删除无关材料。

建议：先根据明确单位、来源标签和材料身份收窄候选，再判断是否歧义；真正同口径但无法绑定的重复集合继续跳过。来源标签匹配需要明确边界，不把较长标签的首个字母当作完整来源。报告归属不足时继续给出原因，不凭数字猜归属。

验收标准：增加不同单位/不同来源材料不会破坏已有明确绑定的检查；同单位且无明确归属的重复数字仍跳过；不能将来源A的结论绑定到来源B。引用仍指向原材料，不合并现实统计口径。

### EBR-04：大整数转为 Number 后可能把不同数量当作相同

**优先级 P2；预计 0.5–1 工程日；可行性高。** 这是正确性边界修复，不是增加算术核查能力。

证据：[src/grounding.js:7](../src/grounding.js#L7) 允许多组千位分隔符；[src/grounding.js:10](../src/grounding.js#L10) 和 [src/grounding.js:25](../src/grounding.js#L25) 直接转换为 `Number`，没有安全整数检查；[src/grounding.js:89](../src/grounding.js#L89) 随后比较转换后的值。

本轮复现：材料“登记9,007,199,254,740,993份文件，其中30份暂停”，报告“9,007,199,254,740,992份是否包含30份？”。两个总量不同，当前却触发 `material.subset.already_explicit`，把不同数字绑定到同一证据。这里使用完全合成的极大数量，只用于验证边界，不代表常见业务规模。

影响：规则自称进行字面数量匹配，却可能返回错误归因；即使发生频率较低，也不应静默四舍五入后形成确定性问题。

建议：正整数用有界的规范十进制字符串或 `BigInt` 比较，保留原文表示；先定义位数上限。最小补丁可先拒绝或明确跳过非安全整数，但不能将它们四舍五入后继续检查。不要把 `BigInt` 原样写入 JSON 结果。

验收标准：上述不同总量不匹配；相同的大整数在支持范围内可精确匹配；覆盖 `MAX_SAFE_INTEGER` 两侧、千位分隔符、负数、错格式及超长整数；保持现有小整数和单位行为，无科学计数法改写证据。

### EBR-05：输入错误缺少机器可读的原因和字段位置

**优先级 P2；预计 0.5–1 工程日；可行性高。** 保留“错误输入不能产生核查通过”的原则，只改善接入诊断，不自动修复或忽略错误。

证据：[src/cli.js:50](../src/cli.js#L50)、[src/cli.js:56](../src/cli.js#L56) 将部分不同原因压成同一通用文本，`--json` 下错误也没有结构化格式；[src/index.js:42](../src/index.js#L42) 的日期引用定位只传固定字段名，丢失材料索引；[src/text.js:36](../src/text.js#L36) 抛出没有错误码或路径的 `TypeError`。现有 [test/cli.test.js:32](../test/cli.test.js#L32) 只保证退出码及不泄漏正文，没有检查可操作诊断。

本轮复现：无效 JSON 与不存在的合成文件都退出2，并返回完全相同的通用英文错误；第二份材料的引用错误只提示 `source.dateQuote`，没有 `materials[1]`、错误码或可定位路径。

影响：CI、Agent 工作流和表单接入只能解析英文消息或逐个字段重试；输入较多时，普通使用者无法知道应该修哪一份材料。当前隐藏路径和正文的安全选择应保留。

建议：增加保持 `TypeError` 兼容的具名错误类型，提供稳定 `code`、JSON Pointer 风格 `path`、安全提示；`--json` 失败时向 stderr 输出版本化错误 JSON，stdout仍为空，退出码仍为2。区分 `input_not_readable`、`invalid_json`、`invalid_utf8`、`limit_exceeded`、`quote_not_found`、`quote_ambiguous` 等类别，不附原文、密钥或本机绝对路径。补一份小型调用方处理样例即可，不新增服务或管理界面。

验收标准：错误可定位到 `/materials/1/source/dateQuote` 等具体字段；机器无需解析自然语言就能分流；同一错误在库和 CLI 使用相同代码；stdout、退出码和不回显敏感内容的原约束不回退。

## 建议的三轮迭代

| 顺序 | 交付范围 | 预估工作量 | 完成条件 |
| --- | --- | --- | --- |
| 迭代1：基础可信度 | EBR-01、EBR-04；补成对正/反例和规则变更说明 | 1.5–3 工程日 | 当前已确认的明确漏报、错误数字归因被修复，否定/条件/定位保护不退化 |
| 迭代2：处理效率与多材料 | EBR-02、EBR-03；缓存、索引、明确身份后再判歧义 | 1.5–3.5 工程日 | 允许输入内重复引用不反复扫描；独立材料不会抑制已明确关系；精确结果保持一致 |
| 迭代3：接入收尾 | EBR-05；小型离线集成样例、类型和发行内容检查 | 0.5–1 工程日 | 调用方可定位并解释输入错误，不把无结果当通过；中英介绍和实际契约一致 |

整体约3.5–7.5工程日，另预留评审时间，不是固定排期。若一次只做最小有用增量，先完成迭代1，再以真实接入长度决定迭代2的性能门槛。不要将需要本地复现的缺陷转化成付费模型评测任务。

后续实施时，每轮只运行相关定向回归；三个迭代合并时再做一次现有全量 Node 测试与 TypeScript 消费契约检查。Node 22/24、Windows/Linux 的小型 CLI 检查作为发布前验证范围，当前不宣称这些矩阵已完成。代码语义或结果契约变更应记录版本，不改写旧验证记录。

## 暂缓事项

- 通用事实真实性、英文通用语义、算术核查、大规模模型评测和自动修订报告：不是本组件当前定位。
- 自动联网、自动解析所有网页、根据一句“最新”推断全部引用关系：会破坏可重复性和显式证据边界。
- 完整 Markdown/HTML 解析器、知识图谱、数据库、后台服务、可视化产品和复杂插件体系：尚无足够收益支撑新增依赖和维护成本。
- 在消除重复扫描前引入 Worker、分布式执行或提高输入上限：先处理确定性浪费；有实际延迟数据后再决定隔离执行需求。
- npm 正式发布、额外托管服务、自动推送/定时评测：本轮未授权实施；后续即使发布也不等同事实核查能力通过。

## 本轮验证与限制

1. 7组功能探针：2组正对照、3种串行漏报、1种不同单位导致的过度跳过、1种安全整数外的错误匹配；均从当前真实源码调用 `reviewReport`，没有改代码。
2. 3档重复引用性能探针：1/16/128条，材料92,489单元、1,800句，单子进程6秒保护；128条进程已终止，没有遗留持续执行的性能任务。
3. 3组错误诊断探针：无效JSON、不存在的合成文件、第二份材料的错误引用；未使用私有数据。
4. 当前运行环境 Node.js `v24.13.1`、Windows。性能为单次观察，不作统计精度或跨机器保证。初次性能探针因临时命令字符串语法错误没有执行库逻辑，修正后才得到上述数据，不把失败准备计入验证结果。
5. 没有运行冗余全量测试，也没有将历史95项测试记录写成今天新通过的结果。没有模型、网络、邮箱、安装、提交或推送。

只有本计划是本轮持久文件变更。后续是否实施以上优化，仍由主任务和用户确认优先级；当前发现均未在产品代码中修复。
